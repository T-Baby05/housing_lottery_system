## 1. 目标

构建还房摇号系统 MVP，跑通以下核心闭环：

```text
导入住户 -> 导入房源 -> 录入意愿 -> 审核锁定 -> 数据封存 -> 四轮摇号 -> 发布结果 -> 住户查询 -> 导出归档
```

## 2. 架构概览

- 后端：Spring Boot 3 单体应用。
- 数据库：MySQL 8.0。
- 数据访问：MyBatis-Plus。
- 前端：Vue 3 + Element Plus + Vite。
- 查询端：可独立 `lottery-query`，也可先在前端工程提供公开路由，待确认。
- 核心算法：独立 `LotteryEngine`，纯函数、可测试、可复现。

## 3. 实施原则

1. 先后端基础和数据库，再实现核心算法，再实现业务 API，最后接前端。
2. 核心算法和关键业务规则必须先写测试，再写实现。
3. 每个任务完成后运行对应测试或构建命令。
4. 优先保证 MVP 闭环，不提前实现完整权限、短信、多项目切换等暂缓能力。
5. 所有提交信息使用中文。
6. 本文是迁移后的计划，不直接复制历史文档中的全部代码片段；代码实现前还应结合最新工程状态拆成 GitHub Issues。

### Task 4：实现 LotteryEngine 核心算法

目标：用严格 TDD 实现确定性摇号核心能力。

文件范围：
- 创建：`lottery-server/src/main/java/.../engine/LotteryEngine.java`
- 创建：`lottery-server/src/main/java/.../engine/LotteryCandidate.java`
- 创建：`lottery-server/src/main/java/.../engine/LotteryDrawResult.java`
- 创建：`lottery-server/src/test/java/.../engine/LotteryEngineTest.java`

TDD 测试清单：
1. 相同候选人、相同种子，输出顺序一致。
2. 不同种子大概率输出不同顺序。
3. 中签数量等于 `min(候选户数, 可用房源数)`。
4. 候选户少于房源时，全部中签。
5. 候选户为空时，结果为空。
6. 输出结果不重复。
7. 洗牌顺序可作为候补顺序。

验证方式：

```bash
cd lottery-server
mvn -Dtest=LotteryEngineTest test
mvn test
```

预期结果：核心算法测试和全量后端测试通过。

待确认：
- PRNG 具体实现是否继续使用 `SHA1PRNG`，还是实现明确规范的确定性 PRNG。
- 是否要求跨 JDK/跨平台复现。

### Task 8：实现摇号执行 API

目标：串联 LotteryEngine 和业务数据，实现 A/B/C/D 四轮摇号。

文件范围：
- 创建：`controller/LotteryController.java`
- 创建：`service/LotteryService.java`
- 创建：`dto/lottery/*`
- 创建：`test/.../LotteryServiceTest.java`

主要工作：
1. 初始化或查询 A/B/C/D 轮次。
2. 开始一轮摇号前校验项目已锁定。
3. 根据当前有效志愿筛选候选人。
4. 根据可用房源数量确定中签数量。
5. 调用 `LotteryEngine` 生成洗牌顺序。
6. 保存本轮种子、候选数、中签数、结果和候补顺序。
7. 已中签住户退出后续轮次。
8. 未中签住户流转到下一有效志愿。
9. 写入审计日志。

验证方式：

```bash
cd lottery-server
mvn -Dtest=LotteryServiceTest test
mvn test
```

预期结果：四轮摇号核心规则测试通过，全量后端测试通过。

待确认：
- 中签后是否立即绑定具体房源编号。
- 重摇、作废、异常中断的处理是否纳入 MVP。

### Task 12：实现住户查询端

目标：提供适配手机扫码访问的查询页面。

实现方案二选一：

方案 A：独立应用 `lottery-query`
- 适合查询端公网部署、管理端内网部署的场景。
- 部署边界清晰，但会增加工程和构建成本。

方案 B：管理端工程内公开路由 `/query`
- 适合 MVP 快速演示。
- 工程更简单，但需要注意后台页面和公开页面访问边界。

主要工作：
1. 查询表单：参与编号 + 身份校验信息。
2. 发布前状态展示。
3. 中签/未中签/候补结果展示。
4. 身份证号和手机号脱敏展示。
5. 移动端适配。

验证方式：

```bash
# 方案 A
cd lottery-query
npm install
npm run build

# 方案 B
cd lottery-admin
npm run build
```

预期结果：手机页面可查询并正确展示结果。

## 8. 完成定义

MVP 实施完成需要满足：

1. 后端测试通过。
2. 前端构建通过。
3. 核心闭环端到端可演示。
4. 摇号算法可通过固定输入和种子复现。
5. 结果发布前不可通过公开查询接口泄露结果。
6. 查询展示脱敏。
7. 关键动作有审计日志。
8. 最终结果可导出。
9. 项目归档后核心数据只读。
10. 关键待确认项已有明确处理结论或延期记录。
