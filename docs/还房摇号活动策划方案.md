# XX项目还房摇号活动策划方案

## 一、文档说明

`文档用途`：用于归档 XX 项目还房摇号活动的组织思路、现场流程和实施要求，作为后续制度细化、系统设计和会务执行的基础版本。  
`文档状态`：方案初稿。  
`适用前提`：默认项目已具备电子摇号系统，支持资格校验、房型意愿导入、分轮摇号、结果查询、日志留痕和结果导出。  
`组织目标`：在 `1 个工作日` 内完成 `900 人次` 规模的集中摇号活动组织，并形成可查询、可公示、可归档的摇号结果。

## 二、编制背景

为替代原有摇珠还房方式，提升还房活动的公开性、公平性、可追溯性和现场组织效率，拟采用电子摇号系统组织 XX 项目还房活动。结合本项目房源结构和参与规模，方案按 `A、B、C、D 四种房型`、`共 700 套房源`、`900 人次参与现场活动` 的场景进行设计。

本方案重点解决以下问题：

1. 如何将大规模参与活动压缩在一天内完成。
2. 如何将传统逐户摇珠的现场等待时间改为系统集中摇号。
3. 如何在保证公平性的前提下，降低现场拥堵和争议。
4. 如何通过二维码查询实现结果即时告知和人员分流。

## 三、总体思路

本次活动采用 `按户参加、提前填报房型意愿、按房型分轮电子摇号、结果即时扫码查询、后续分批确认` 的组织模式。

总体逻辑如下：

1. 以 `有效还房户` 作为摇号主体，不以自然人作为摇号主体。
2. 每户在活动前填报房型意愿，建议按优先顺序填写 `1-4 个志愿`。
3. 系统按房型建立摇号池，依次对 `A、B、C、D` 四类房型开展摇号。
4. 每轮摇号完成后，系统即时更新结果，并开放统一二维码查询入口。
5. 已中签并锁定结果的住户自动退出后续轮次，未中签住户按规则进入下一有效志愿。
6. 当日完成摇号、公示、查询、异议登记和结果确认安排，具体房号确认可在当日分批办理或按后续通知组织。

该模式的核心是将原先大量分散的人工动作收敛为 `4 轮集中摇号`，把现场时间从“逐户排队处理”转为“集中出结果、分散查询、统一归档”。

## 四、活动目标

1. 在一天内完成四类房型的集中摇号活动。
2. 实现摇号过程公开透明、结果可查、操作可追溯。
3. 控制现场秩序，避免 900 人次长时间聚集等待。
4. 通过电子查询减轻现场咨询压力，提升参与体验。
5. 为后续房号确认、结果公示和档案归集提供准确数据基础。

## 五、基本原则

1. `公开原则`：摇号规则、房源数量、参与名单、轮次顺序和结果生成方式提前公开。
2. `公平原则`：所有有效参与对象在统一规则下进入对应摇号池，随机生成结果。
3. `留痕原则`：关键动作均由系统记录日志，保留时间、操作人、结果状态和导出记录。
4. `高效原则`：线下活动聚焦宣讲、见证和结果发布，查询动作尽量线上化。
5. `稳定原则`：系统、数据、设备、网络、打印均需设置备用方案。
6. `隐私原则`：大屏和二维码查询均采用脱敏展示，避免泄露个人敏感信息。

## 六、活动规模与组织方式

### 6.1 规模假设

1. 现场参与规模：`900 人次`。
2. 房源规模：`700 套`。
3. 房型类别：`A、B、C、D` 四类。
4. 摇号轮次：`4 轮`。
5. 摇号主体：`有效还房户`。

### 6.2 组织判断

在电子摇号前提下，本项目 `可以组织为一天内完成的集中摇号活动`，但前提是对活动边界作如下界定：

1. 当日完成的是 `资格确认、规则宣讲、四轮摇号、结果查询、结果汇总、异议登记`。
2. 当日如具备条件，可同步办理部分 `结果确认`。
3. 如涉及具体房号、楼层、朝向等再次选择，建议安排在后续专门确认环节，不与主摇号大会混在同一主流程中。

换言之，本方案的一日活动目标是 `在一天内完成摇号主活动`，而不是在主会场内完成 700 套房屋的逐套人工处置。

## 七、前置条件

为保证当天活动顺畅，以下事项须在活动前完成并封存：

1. 有效还房户名单确认。
2. 房源总量及 A、B、C、D 各房型数量确认。
3. 每户房型意愿采集、核对和签字确认。
4. 代理参与规则、弃选规则、异议处理规则确认。
5. 二维码查询页面联调完成。
6. 现场网络、电源、大屏、打印、备用设备测试完成。

## 八、参与规则设计

### 8.1 摇号主体

本活动以 `户` 为最小参与单位。每户对应一个唯一参与编号，系统围绕该编号完成资格校验、摇号、结果查询和归档。

### 8.2 房型意愿填报

为减少热门房型超额后的现场争议，建议采用 `多志愿填报` 机制：

1. 每户至少填报 `1 个` 房型意愿。
2. 每户最多可填报 `4 个` 房型意愿，并明确优先顺序。
3. 活动截止后，房型意愿一律封存，不得现场临时变更。

### 8.3 分轮摇号规则

1. 第一轮为 `A 户型摇号`。
2. 第二轮为 `B 户型摇号`。
3. 第三轮为 `C 户型摇号`。
4. 第四轮为 `D 户型摇号`。
5. 每轮仅允许进入该房型有效意愿池的住户参与摇号。
6. 已在前序轮次中签并锁定结果的住户，不再参加后续轮次。
7. 未中签住户按其已填报的下一有效志愿自动流转至下一轮。

### 8.4 结果状态

每户在任一时点仅存在一种有效状态：

1. `待参与`：尚未进入对应轮次。
2. `参与未中签`：本轮未中签，等待下一有效志愿。
3. `中签待确认`：已获得结果，待后续确认。
4. `已确认`：已完成结果确认。
5. `弃选/无效`：因规则原因退出后续流程。

## 九、活动组织架构

### 9.1 组织机构

建议设立以下工作组：

1. `综合协调组`：负责总控调度、进度衔接、部门联动。
2. `资格审核组`：负责签到核验、证件审查、代理授权审核。
3. `规则宣讲组`：负责政策说明、流程讲解、现场答疑。
4. `系统保障组`：负责系统运行、轮次启动、数据备份、故障切换。
5. `会场秩序组`：负责引导分流、人员疏导、安保协同。
6. `结果服务组`：负责二维码查询指导、人工查询补充、咨询受理。
7. `监督见证组`：负责活动关键节点见证、监督和签认。
8. `档案归集组`：负责结果导出、打印、资料归档和影像留存。

### 9.2 建议人员配置

| 工作组 | 建议人数 | 主要职责 |
| --- | --- | --- |
| 综合协调组 | 3 人 | 总体指挥、节点把控、突发事项决策 |
| 资格审核组 | 6 人 | 签到、身份核验、代理材料审核 |
| 规则宣讲组 | 2 人 | 主持、规则讲解、统一口径答疑 |
| 系统保障组 | 4 人 | 系统操作、轮次控制、技术值守 |
| 会场秩序组 | 8 人 | 入场引导、候场秩序、应急疏导 |
| 结果服务组 | 6 人 | 查询辅导、咨询解答、人工复核 |
| 监督见证组 | 2-4 人 | 关键节点监督、公证见证 |
| 档案归集组 | 4 人 | 结果导出、文书打印、资料封存 |

## 十、现场区域设置

建议采用单向流线布置，至少设置以下区域：

1. `签到核验区`：负责身份核验和入场管理。
2. `候场等候区`：供参与对象观看流程说明和轮次进展。
3. `主会场`：用于规则宣讲、监督见证、轮次启动和大屏展示。
4. `查询服务区`：用于二维码查询辅导和人工辅助查询。
5. `咨询受理区`：用于政策解释、异议登记和特殊情况处理。
6. `资料办理区`：用于结果确认、打印和档案签收。
7. `设备保障区`：放置备用电脑、打印机、网络和电源设备。

## 十一、活动流程

### 11.1 活动前阶段

1. 发布活动通知，告知时间、地点、材料要求和注意事项。
2. 组织还房户完成房型意愿填报和确认。
3. 完成有效名单、房源数量和志愿数据复核。
4. 完成系统导入、逻辑校验和全流程演练。
5. 生成统一查询二维码并测试访问稳定性。
6. 准备纸质预案、人工台账和备用公示清单。

### 11.2 活动当天主流程

1. 参与对象签到入场并完成身份核验。
2. 主持人宣布活动开始，介绍出席监督人员和活动纪律。
3. 宣读摇号规则、房型轮次规则、查询方式和异议受理方式。
4. 公布并确认封存数据，包括名单、房源、意愿和轮次设置。
5. 在监督见证下启动 `A 户型摇号`。
6. 系统生成 A 户型结果并同步开放二维码查询。
7. 在监督见证下启动 `B 户型摇号`。
8. 系统生成 B 户型结果并同步开放二维码查询。
9. 在监督见证下启动 `C 户型摇号`。
10. 系统生成 C 户型结果并同步开放二维码查询。
11. 在监督见证下启动 `D 户型摇号`。
12. 系统生成 D 户型结果并同步开放二维码查询。
13. 汇总四轮结果，形成最终结果表、候补顺序表和异常记录表。
14. 现场受理查询辅导和异议登记，说明后续确认安排。
15. 完成数据导出、资料封存和活动结束确认。

### 11.3 当日建议时序

| 时间 | 环节 | 说明 |
| --- | --- | --- |
| 08:00-09:00 | 签到核验 | 分批入场，避免集中拥堵 |
| 09:00-09:20 | 开场及规则宣讲 | 统一解释规则和纪律 |
| 09:20-09:30 | 数据封存确认 | 名单、房源、志愿、轮次确认 |
| 09:30-09:50 | A 户型摇号 | 结果生成并开放查询 |
| 09:50-10:10 | B 户型摇号 | 结果生成并开放查询 |
| 10:10-10:30 | C 户型摇号 | 结果生成并开放查询 |
| 10:30-10:50 | D 户型摇号 | 结果生成并开放查询 |
| 10:50-11:20 | 结果汇总公布 | 公布统计结果和后续安排 |
| 11:20-12:00 | 查询辅导与异议登记 | 现场咨询和问题收集 |
| 14:00-17:00 | 结果确认或后续安排办理 | 可视项目实际决定是否当天办理 |

## 十二、二维码查询方案

二维码查询是本次活动的重要配套机制，主要作用是 `即时告知结果、分散现场人流、减少人工咨询压力`。

### 12.1 查询方式

1. 全场使用 `统一查询二维码`。
2. 参与对象扫码后进入结果查询页面。
3. 查询时应通过 `参与编号 + 身份校验信息` 完成身份验证。
4. 每轮摇号结束后，系统自动更新查询结果，无需重新更换二维码。

### 12.2 查询内容

查询页面建议展示以下信息：

1. 参与编号和姓名脱敏信息。
2. 当前资格状态。
3. 已填报房型意愿顺序。
4. 已参与轮次及对应结果。
5. 当前是否中签。
6. 如未中签，是否进入下一有效志愿。
7. 最终结果或候补顺序。
8. 后续确认时间、地点和所需材料。

### 12.3 展示边界

1. 二维码页面不展示完整身份证号码、电话等敏感信息。
2. 会场大屏以统计信息和脱敏编号展示为主。
3. 如需人工辅助查询，应由工作人员在授权区域内操作。

## 十三、现场公示与展示方案

### 13.1 主会场大屏展示

每轮建议展示以下内容：

1. 当前房型名称。
2. 当前房型房源数量。
3. 当前轮次参与户数。
4. 当前轮次中签户数。
5. 剩余待处理情况。
6. 脱敏后的中签编号或顺序编号。

### 13.2 结果公示

活动结束后，应形成并留存以下成果：

1. 房型轮次结果表。
2. 最终结果汇总表。
3. 候补顺序表。
4. 异议登记表。
5. 系统操作日志。
6. 现场影像资料。

## 十四、重点规则说明

为减少现场争议，以下规则须在活动通知和现场宣讲中明确：

1. 摇号主体为 `户`，不是到场人数。
2. 到场签到不改变摇号资格和参与顺序。
3. 房型意愿以活动截止前最终确认版本为准。
4. 已中签住户自动锁定并退出后续轮次。
5. 未中签住户按规则流转至下一有效志愿。
6. 当日摇号结果以系统记录和监督确认结果为准。
7. 如涉及具体房号确认，应按照后续通知或当日安排另行办理。
8. 异议受理只做登记和复核，不中断四轮主流程。

## 十五、风险点与应对措施

| 风险事项 | 可能影响 | 应对措施 |
| --- | --- | --- |
| 房型意愿规则不清 | 现场争议增多 | 提前公示规则，现场统一宣讲并书面确认 |
| 同户重复中签 | 结果失真 | 系统设置中签锁定机制，禁止重复进入后续轮次 |
| 查询量集中 | 二维码访问拥堵 | 提前压测，准备人工查询台和备用网络 |
| 网络或设备故障 | 活动中断 | 准备局域网、备用电脑、备用打印机和 UPS |
| 现场人员聚集 | 秩序混乱 | 单向流线、分区引导、查询分流、安保协同 |
| 对具体房号认知不足 | 误解结果 | 明确区分“房型摇号结果”和“具体房号确认”两个环节 |
| 异议集中爆发 | 主流程受阻 | 设独立咨询受理区，不在主会场逐一解释 |

## 十六、物料与保障建议

### 16.1 设备物料

1. 主持电脑、系统操作电脑、备用电脑。
2. 大屏、投影、音响、话筒。
3. 打印机、备用打印机、纸张和耗材。
4. 网络设备、备用热点、UPS 电源。

### 16.2 会务物料

1. 签到表、工作证、桌牌、引导牌。
2. 规则摘要单、流程说明单、查询指引单。
3. 异议登记表、情况说明表、授权委托样表。
4. 现场公示牌、提示牌和隔离带。

## 十七、成果输出与归档要求

活动结束后，应完成以下归档工作：

1. 导出最终摇号结果并形成电子版归档文件。
2. 打印关键结果清单并由相关负责人签字确认。
3. 整理系统日志、操作记录和时间节点记录。
4. 留存签到资料、异议登记资料和授权代理资料。
5. 留存现场照片、视频等影像资料。
6. 形成活动总结，为后续系统优化和制度完善提供依据。

## 十八、方案结论

基于本项目 `700 套房源、900 人次参与、4 种房型` 的组织条件，采用 `按房型分轮电子摇号 + 统一二维码查询` 的模式，能够将原本分散、耗时、易拥堵的传统摇珠活动，压缩为 `一天内可完成的集中摇号主活动`。

本方案的关键优势在于：

1. 将主会场核心动作压缩为四轮摇号，显著缩短现场时长。
2. 通过二维码查询替代大量人工答疑和结果传递，提升效率。
3. 通过中签锁定、自动流转和日志留痕，保证规则执行的一致性。
4. 通过将“摇号结果生成”与“后续房号确认”适度分离，提高整体组织稳定性。

后续如进入系统设计阶段，可在本方案基础上继续细化为：

1. 摇号规则细则。
2. 系统功能清单。
3. 角色权限和现场操作流程。
4. 页面原型和数据流转方案。
