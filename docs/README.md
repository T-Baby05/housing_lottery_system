# 项目文档中心

本目录用于统一管理项目生命周期内的所有文档，包括项目背景、需求、方案、设计、实施计划、架构决策、测试、发布和复盘材料。

## 文档目录

| 目录 | 用途 | 典型内容 |
| --- | --- | --- |
| `00-project/` | 项目级基础信息与协作规范 | 项目概览、术语表、路线图、工作流、GitHub 规范、文档规范 |
| `01-requirements/` | 需求文档 | 业务需求、用户故事、验收标准、范围边界 |
| `02-solutions/` | 方案文档 | 业务方案、产品方案、技术选型方案、MVP 范围方案 |
| `03-designs/` | 设计文档 | 架构设计、数据库设计、接口设计、算法设计、原型映射 |
| `04-plans/` | 实施计划 | 任务拆分、开发计划、里程碑、执行清单 |
| `05-adr/` | 架构决策记录 | 重要技术/架构/流程决策及取舍原因 |
| `06-testing/` | 测试与验收 | 测试策略、测试用例、验收清单、测试报告 |
| `07-releases/` | 发布与交付 | 发布说明、部署步骤、变更记录、已知问题 |
| `08-reviews/` | 复盘与总结 | 阶段复盘、问题总结、改进项 |
| `templates/` | 文档模板 | 各类标准文档模板 |
| `assets/` | 文档素材 | 图片、图表、样例数据、附件 |
| `superpowers/` | 历史 Agent 产出 | 早期 specs/plans 文档，后续逐步迁移到标准目录 |

## 文档状态

建议在每份正式文档顶部标明状态：

- `Draft`：草稿，正在编写或讨论
- `Reviewing`：评审中，等待确认
- `Accepted`：已确认，可作为执行依据
- `Superseded`：已被新文档替代
- `Archived`：已归档，仅保留历史参考

## 命名规范

普通文档：

```text
YYYY-MM-DD-中文主题-文档类型.md
```

示例：

```text
2026-05-11-MVP范围方案.md
2026-05-11-摇号引擎技术设计.md
2026-05-11-MVP实施计划.md
```

ADR 文档：

```text
0001-中文决策标题.md
```

示例：

```text
0001-采用SpringBoot单体架构.md
0002-采用确定性摇号引擎.md
```

## 推荐工作方式

1. 新需求先进入 `01-requirements/`。
2. 存在多个做法或需要业务/技术取舍时，进入 `02-solutions/`。
3. 方案确定后，进入 `03-designs/` 形成可开发设计。
4. 开发前在 `04-plans/` 拆成可执行任务。
5. 重要决策同步记录到 `05-adr/`。
6. 开发完成后补齐 `06-testing/`、`07-releases/` 和 `08-reviews/`。

## 当前整理策略

本次整改先建立标准目录、规范和模板，不直接移动历史文档，避免破坏已有引用。历史文档后续按文档类型逐步迁移或在索引中建立映射。
