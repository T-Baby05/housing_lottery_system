## 1. 文档目的

本文从历史需求分析文档迁移而来，用于沉淀还房系统的业务背景、产品目标、核心概念、角色权限、功能模块、业务规则、非功能需求和分期边界。

需要特别说明：历史需求文档描述的是较完整的“多项目还房业务管理平台”，范围大于当前 MVP。本文会保留全量平台方向，同时标注哪些内容属于 MVP 必做、哪些内容应暂缓。

## 2. 建设背景

为替代原有摇珠还房方式，并支撑后续多项目、多轮次的电子化还房活动，需要建设一套可复用、可归档、可配置、可追溯的还房系统。

系统不仅要解决摇号本身的问题，还要覆盖以下业务链条：

1. 项目启动与基础配置。
2. 还房户信息采集与意愿管理。
3. 房源数据管理与资格审核。
4. 电子摇号与结果发布。
5. 通知、二维码查询、现场执行支持。
6. 结果确认、公示复核、资料归档。

需求评估：当前 MVP 不应一次性实现完整平台能力，应优先验证“数据锁定 + 四轮摇号 + 结果查询 + 导出归档”的核心闭环。

## 3. 产品目标

### 3.1 业务目标

| 目标 | MVP 处理方式 |
| --- | --- |
| 支持一个系统下管理多个还房项目 | MVP 先单项目运行，表结构保留 `project_id` |
| 支持不同项目之间数据、规则、活动和结果隔离 | MVP 做结构预留，完整项目切换后续扩展 |
| 支持从前期准备到活动收尾的完整业务闭环 | MVP 覆盖核心摇号闭环 |
| 支持电子摇号替代传统摇珠 | MVP 必做 |

### 3.2 管理目标

1. 统一管理还房户、房源、意愿、摇号、通知和归档数据。
2. 支持项目全过程可视化推进。
3. 支持多人分角色协作和权限控制。

MVP 处理方式：
- 住户、房源、意愿、摇号、结果归档进入 MVP。
- 完整通知、复杂权限和全过程可视化暂缓或简化。

### 3.3 风控目标

1. 保证摇号规则统一、结果可追溯。
2. 保证操作留痕、关键数据可封存。
3. 保证项目间互不串数、互不误操作。

MVP 处理方式：
- 数据锁定、SHA-256 哈希、摇号种子、操作日志进入 MVP。
- 完整项目间权限隔离后续扩展。

### 3.4 服务目标

1. 支持短信通知、查询二维码和现场结果查询。
2. 降低现场人工解释和查号压力。
3. 提升群众参与体验和结果获取效率。

MVP 处理方式：
- 公开查询页进入 MVP。
- 真实短信暂缓，用导出名单和人工通知替代。
- 现场签到、打印、异常登记暂缓。

## 4. 系统定位与边界

### 4.1 系统定位

系统长期定位为多项目还房业务管理平台，围绕每一个还房项目完成项目配置、住户管理、房源管理、意愿管理、摇号执行、结果发布和归档留痕。

MVP 阶段定位为现场活动核心支撑系统，重点证明还房摇号主流程可运行、可审计、可查询、可归档。

### 4.2 本期不重点建设内容

| 暂缓内容 | 暂缓原因 |
| --- | --- |
| 财务结算、缴费和票据管理 | 与摇号核心闭环弱相关 |
| 电子签章平台深度对接 | 依赖外部平台和流程确认 |
| 外部政务系统复杂双向数据交换 | 数据边界和接口不确定 |
| 面向公众的完整小程序生态 | MVP 用移动 Web 查询页即可 |
| 三维选房、可视化楼盘建模 | 展示成本高，非核心验证目标 |
| 真实短信通知 | 服务商、模板、费用和失败重试机制未定 |
| 完整用户/角色/菜单管理 | 早期会拖慢核心闭环 |

## 5. 核心概念

### 5.1 项目

项目是系统最高层级的业务对象，也是数据隔离边界。

项目基础信息建议包括：

| 字段 | 说明 | MVP 处理方式 |
| --- | --- | --- |
| 项目名称 | 业务展示名称 | 必做 |
| 项目编码 | 系统唯一识别编码 | 必做 |
| 项目简称 | 列表和报表展示用简称 | 可选 |
| 项目状态 | 草稿、准备中、锁定、摇号中、结束、归档等 | 必做简化状态 |
| 项目时间 | 项目启动时间、活动时间、归档时间 | 可选或简化 |
| 项目说明 | 项目背景、规则说明、备注 | 可选 |
| 负责人 | 项目负责人及联系方式 | 可选 |
| 适用规则 | 当前项目采用的摇号规则版本 | 后续扩展 |

### 5.2 项目级隔离要求

长期平台要求实现业务隔离、数据隔离、权限隔离和展示隔离。

| 隔离对象 | 长期要求 | MVP 处理方式 |
| --- | --- | --- |
| 住户数据 | 项目内住户不能被其他项目查看和误操作 | 表保留 `project_id` |
| 房源数据 | 房源只能归属一个项目 | 表保留 `project_id` |
| 房型意愿 | 意愿归属于具体项目 | 通过住户/项目间接关联 |
| 摇号轮次 | 轮次、结果、候补顺序按项目管理 | 必做 |
| 查询二维码 | 每个项目生成独立查询入口 | 可先固定查询入口，后续项目化 |
| 短信通知 | 通知内容和记录按项目归档 | 暂缓真实短信 |
| 操作日志 | 关键操作追溯到项目维度 | 必做 |
| 权限授权 | 用户可在某项目有权限、另一项目无权限 | 暂缓完整项目级授权 |

### 5.3 项目生命周期

历史需求建议状态：

```text
草稿 -> 准备中 -> 报名中 -> 锁定中 -> 待摇号 -> 摇号中 -> 已结束 -> 已归档
```

MVP 建议简化状态：

```text
PREPARING -> LOCKED -> LOTTERY -> FINISHED -> ARCHIVED
```

待确认：是否需要保留 `DRAFT` 或 `待摇号` 状态作为后台展示状态。

## 6. 用户角色与权限

### 6.1 长期角色建议

| 角色 | 权限范围 | 说明 | MVP 处理方式 |
| --- | --- | --- | --- |
| 系统管理员 | 全系统 | 用户、角色、参数、字典、日志和系统配置 | 暂缓完整能力 |
| 项目管理员 | 指定项目 | 项目配置、人员授权、状态推进 | MVP 简化为管理员 |
| 数据专员 | 指定项目 | 住户、房源、意愿、导入导出和数据修正 | MVP 覆盖能力 |
| 审核专员 | 指定项目 | 资格审核、异常处理、锁定确认 | MVP 覆盖能力 |
| 摇号操作员 | 指定项目 | 摇号执行、轮次控制、结果导出 | MVP 覆盖能力 |
| 现场服务人员 | 指定项目 | 签到核验、结果查询辅助、打印服务 | 暂缓 |
| 查询用户 | 指定项目 | 仅可查询本人结果 | MVP 必做 |
| 监督人员 | 指定项目 | 查看过程、结果和日志，不直接修改 | 暂缓独立后台视图 |

### 6.2 权限原则

1. 菜单权限按角色控制。
2. 数据权限按项目控制。
3. 关键操作需二次确认。
4. 锁定后核心数据默认只读。
5. 摇号执行、结果发布、项目归档等关键动作需要更高权限门槛。

MVP 待确认：鉴权方案使用临时放行、Basic、Session 还是 JWT。

## 7. 业务总体流程

完整业务流程：

```text
创建项目 -> 配置规则/房型/轮次 -> 导入住户 -> 导入房源 -> 采集意愿 -> 审核资格 -> 锁定数据 -> 通知/二维码 -> 模拟演练 -> 正式摇号 -> 发布查询 -> 公示复核 -> 导出归档
```

MVP 核心流程：

```text
导入住户 -> 导入房源 -> 录入意愿 -> 审核锁定 -> 数据封存 -> 四轮摇号 -> 发布结果 -> 住户查询 -> 导出归档
```

## 8. 功能架构

历史需求按“1 个项目中心 + 8 个业务中心 + 1 个系统管理中心”划分。

| 一级模块 | 模块定位 | MVP 处理方式 |
| --- | --- | --- |
| 项目中心 | 管理多个还房项目及其配置边界 | 简化为单项目工作台和状态控制 |
| 基础配置中心 | 配置项目规则、房型、轮次、字典、模板 | 固定 A/B/C/D 和基础规则，暂缓配置化 |
| 住户管理中心 | 管理还房户基础信息和参与资格 | MVP 必做 |
| 房源管理中心 | 管理房源、房型和可用状态 | MVP 必做 |
| 意愿与审核中心 | 管理房型意愿、资格审核、名单锁定 | MVP 必做 |
| 摇号管理中心 | 管理轮次、试摇、正式摇号、结果生成 | MVP 必做，试摇/暂停/继续可简化 |
| 通知与查询中心 | 管理短信通知、二维码查询、结果展示 | 查询必做，真实短信暂缓 |
| 现场执行中心 | 管理签到、核验、打印、现场服务支持 | 暂缓 |
| 结果与归档中心 | 管理公示、复核、确认、报表、归档 | 导出和归档必做，复杂复核暂缓 |
| 系统管理中心 | 管理用户、角色、参数、日志和安全设置 | 日志必做，完整系统管理暂缓 |

## 9. 详细功能需求

### 9.1 项目中心

主要功能：
1. 新建项目。
2. 编辑项目基础信息。
3. 设置项目负责人和参与人员。
4. 切换当前操作项目。
5. 查看项目总体进度和统计概览。
6. 控制项目状态流转。
7. 项目归档与只读管理。

MVP 范围：
- 初始化一个演示项目。
- 展示项目状态和统计概览。
- 控制锁定、摇号中、完成、归档等关键状态。
- 多项目切换和项目成员授权暂缓。

### 9.2 基础配置中心

主要功能：
1. 配置房型字典，如 A/B/C/D。
2. 配置房型数量、规则说明、展示顺序。
3. 配置摇号轮次和轮次顺序。
4. 配置意愿填报方式。
5. 配置中签规则、未中签流转规则、弃选规则。
6. 配置短信模板、通知模板和公示模板。
7. 配置项目编号、户编号、房源编号规则。

MVP 范围：
- 固定 A/B/C/D 四类房型。
- 固定四轮摇号顺序。
- 固化“已中签退出、未中签进入下一有效志愿”规则。
- 模板配置、规则版本管理暂缓。

### 9.3 住户管理中心

主要功能：
1. 新增、编辑、删除住户信息。
2. 批量导入住户数据。
3. 管理家庭成员、证件、联系方式、代理信息。
4. 管理参与编号和资格状态。
5. 支持按姓名、编号、证件号、手机号查询。
6. 支持批量导出住户清单。

MVP 范围：
- Excel 导入住户。
- 住户列表和筛选。
- 参与编号、户主姓名、身份证号、手机号、家庭人数、资格状态、摇号状态。
- 家庭成员、代理信息可先简化或暂缓。

### 9.4 房源管理中心

主要功能：
1. 导入房源清单。
2. 管理楼栋、单元、楼层、房号、面积、朝向等字段。
3. 将房源归类到具体房型。
4. 维护房源状态。
5. 查看房型数量统计和房源分布。
6. 导出房源台账。

MVP 范围：
- Excel 导入房源。
- 房源列表和筛选。
- 房型 A/B/C/D。
- 房源状态：可用、预留、已分配。
- 朝向、复杂楼栋可视化暂缓。

### 9.5 意愿与审核中心

主要功能：
1. 录入住户房型意愿。
2. 支持一户多志愿顺序填写。
3. 支持批量导入房型意愿。
4. 支持意愿确认单导出。
5. 审核资格、意愿、代理材料和异常状态。
6. 生成最终参与名单。
7. 锁定住户名单、意愿数据和资格状态。

MVP 范围：
- 每户录入 1-4 个房型意愿。
- 审核确认和名单锁定。
- 锁定后生成数据快照和 SHA-256 哈希。
- 代理材料、确认单导出可暂缓。

### 9.6 摇号管理中心

主要功能：
1. 按项目配置生成摇号轮次。
2. 支持模拟摇号或演练摇号。
3. 支持正式摇号启动、暂停、继续和结束。
4. 支持按房型建立摇号池。
5. 支持中签锁定和未中签自动流转。
6. 生成轮次结果、最终结果和候补顺序。
7. 记录摇号时间、操作人、结果摘要和日志。

MVP 范围：
- A/B/C/D 四轮正式摇号。
- 每轮按当前有效意愿筛选候选户。
- 每轮按可用房源数量确定中签数量。
- 保存随机种子、候选数量、中签数量、洗牌顺序和结果。
- 暂缓暂停/继续、复杂重摇流程。

### 9.7 通知与查询中心

主要功能：
1. 批量发送短信通知。
2. 管理短信发送对象、模板和状态。
3. 为项目生成统一查询二维码。
4. 提供查询页面给住户查看本人结果。
5. 支持摇号轮次结果实时更新。
6. 支持公示名单导出和查询页展示控制。

MVP 范围：
- 提供公开查询接口和查询页。
- 查询条件为参与编号 + 身份信息后几位或其他简化校验方式。
- 结果发布前不展示正式结果。
- 查询结果脱敏展示。
- 真实短信和发送记录暂缓。

### 9.8 现场执行中心

主要功能：
1. 签到核验。
2. 代理材料核验。
3. 现场快速查询。
4. 打印签到单、结果单、确认单。
5. 大屏展示数据接口。
6. 现场服务记录和异常登记。

MVP 范围：
- 大屏展示可先固定展示或暂用原型。
- 签到、打印、异常登记暂缓。

### 9.9 结果与归档中心

主要功能：
1. 导出轮次结果表、最终结果表、候补表。
2. 管理结果公示。
3. 受理异议登记和复核记录。
4. 记录结果确认情况。
5. 归集项目资料、影像资料和日志。
6. 项目归档和历史查询。

MVP 范围：
- 导出轮次结果或最终结果。
- 发布结果。
- 项目归档状态。
- 归档后核心数据只读。
- 异议登记、影像资料归档暂缓。

### 9.10 系统管理中心

主要功能：
1. 用户管理。
2. 角色与权限管理。
3. 数据字典管理。
4. 系统参数管理。
5. 操作日志、登录日志查看。
6. 通知模板、打印模板维护。

MVP 范围：
- 关键操作日志必做。
- 完整用户、角色、字典、模板管理暂缓。

## 10. 关键业务规则

1. 摇号主体按户管理，不按自然人管理。
2. 一个项目内每户只允许存在一个有效参与编号。
3. 房型意愿必须归属到具体项目。
4. 锁定后的住户名单、房型意愿、房源池默认不可随意修改。
5. 正式摇号仅可对锁定数据执行。
6. 已中签住户自动退出后续轮次。
7. 未中签住户按有效规则进入下一志愿。
8. 查询结果应以系统正式发布结果为准。
9. 项目归档后仅允许查询和导出，不再允许正常业务编辑。

待确认：
- “下一有效志愿”的精确定义。
- 是否允许重摇、作废、解锁。
- 摇号结果是否直接绑定具体房源编号。

| 摇号结果 | 轮次结果、最终结果、候补结果 | 必做 |

| 查询记录 | 二维码访问和查询日志 | 可选 |
| 归档资料 | 报表、附件、影像和操作日志 | 简化实现 |

## 12. 非功能需求

### 12.1 安全性

1. 后台访问需要账号认证。
2. 关键数据需要操作日志和权限控制。
3. 查询页面只展示脱敏数据。
4. 项目间数据不可越权查看。

MVP 待确认：
- 鉴权实现方式。
- 身份证号和手机号是否字段级加密。
- 查询校验使用身份证后四位、手机号后四位还是组合。

### 12.2 稳定性

1. 摇号活动期间系统需保持稳定运行。
2. 应支持数据备份和故障恢复。
3. 应支持导出关键清单以备离线应急。

### 12.3 可追溯性

1. 关键业务动作应全程留痕。
2. 数据导入、数据修正、锁定、摇号、发布、归档应可回看。
3. 摇号种子、输入哈希和结果顺序应可复核。

### 12.4 易用性

1. 后台应围绕项目组织菜单和数据。
2. 现场操作界面应简洁高效。
3. 查询入口应简单易懂，适配手机访问。

## 13. 分期建议

### 13.1 MVP 优先建设

1. 单项目基础能力，表结构保留 `project_id`。
2. 住户管理。
3. 房源管理。
4. 意愿与审核锁定。
5. A/B/C/D 四轮电子摇号。
6. 公开查询。
7. 结果导出和归档。
8. 操作日志。

### 13.2 MVP 暂缓建设

1. 多项目完整切换。
2. 完整项目级权限。
3. 真实短信通知。
4. 现场签到、打印、异常登记完整流程。
5. 复杂归档流程。
6. 大屏模板管理。
7. 外部系统对接。
8. 电子签章、缴费和票据。

### 13.3 二期可扩展方向

1. 在线意愿填报端。
2. 电子签字或签章集成。
3. 大屏展示模板管理。
4. 更复杂的选房确认流程。
5. 与其他业务系统的数据对接。
6. 项目模板复制和规则模板复用。

## 14. 验收标准

### 14.1 MVP 业务验收

- [ ] 可以导入住户。
- [ ] 可以导入房源。
- [ ] 可以录入或导入每户意愿。
- [ ] 可以审核并锁定数据。
- [ ] 锁定后生成数据快照哈希。
- [ ] 可以执行 A/B/C/D 四轮摇号。
- [ ] 已中签住户不会进入后续轮次。
- [ ] 未中签住户按下一有效志愿流转。
- [ ] 可以发布结果。
- [ ] 住户可以通过公开查询页查询本人结果。
- [ ] 查询结果脱敏展示。
- [ ] 可以导出最终结果。
- [ ] 项目归档后核心数据只读。

### 14.2 非功能验收

- [ ] 关键动作有操作日志。
- [ ] 锁定后核心数据不可直接修改。
- [ ] 结果发布前查询端不泄露正式结果。
- [ ] 摇号输入、种子、结果可追溯。
- [ ] 关键清单可导出作为离线应急材料。
