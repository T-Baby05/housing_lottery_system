# 还房系统一期原型信息架构与页面映射

## 1. 文档定位

本文件用于把现有策划与需求文档，收敛成一套可直接演示的原型结构说明。当前原型不是单一的“摇号页面”，而是一个围绕 `项目` 运转的多项目还房业务平台 Demo。

原型入口：

- `prototype/index.html`
- `prototype/query.html`

## 2. 文档分析结论

### 2.1 系统定位

根据 [还房系统需求分析与功能划分](./还房系统需求分析与功能划分.md) 与 [还房摇号活动策划方案](./还房摇号活动策划方案.md)，本系统的核心定位是：

1. 以 `项目` 作为最高业务边界。
2. 以 `住户、房源、意愿、锁定、摇号、发布、归档` 为主流程。
3. 同时覆盖后台管理、现场执行、住户查询三类使用场景。

### 2.2 一期必须被看见的能力

一期原型优先体现以下能力：

1. 多项目切换与项目隔离。
2. 住户、房源、意愿、审核、摇号结果的关联关系。
3. `锁定 -> 摇号 -> 发布 -> 归档` 四个关键状态。
4. 住户查询页与后台发布状态同步。
5. 活动当天的现场签到、快速查询、打印占位与异常登记入口。

### 2.3 核心角色

原型中重点体现以下角色视角：

1. 项目管理员：切项目、看进度、控状态。
2. 数据专员：维护住户、房源、意愿与审核。
3. 摇号操作员：执行四轮摇号并查看结果。
4. 现场服务人员：签到核验、快速查号、打印占位。
5. 查询用户：通过参与编号与身份校验查询本人结果。

## 3. 核心对象与关键规则

### 3.1 核心对象

原型内部统一围绕以下对象组织演示数据：

1. `Project`
2. `Household`
3. `Unit`
4. `Wish`
5. `ReviewRecord`
6. `LotteryRound`
7. `LotteryResult`
8. `NotificationRecord`
9. `OnsiteCheckin`

### 3.2 关键规则

原型固化以下规则，用于支撑演示闭环：

1. 摇号主体按 `户` 管理。
2. 每户按优先顺序填写 `1-4 个志愿`。
3. 项目未锁定时，不允许执行正式摇号。
4. 四轮摇号固定为 `A / B / C / D`。
5. 已中签住户自动退出后续轮次。
6. 未中签住户进入下一有效志愿对应轮次。
7. 结果未发布前，查询页不能返回正式结果。
8. 项目归档后，所有后台页面进入只读态。

## 4. 原型页面结构

第一版原型采用 `10 页核心链路`：

| 页面 | 文件 | 页面目标 |
| --- | --- | --- |
| 项目工作台 | `prototype/index.html` | 作为后台入口，展示多项目总览、关键指标、推荐演示路径 |
| 项目详情/阶段总览 | `prototype/project-overview.html` | 展示项目基本信息、阶段时间线、活动日安排和里程碑 |
| 住户管理 | `prototype/households.html` | 展示住户台账、资格状态、家庭成员、代理信息 |
| 房源管理 | `prototype/units.html` | 展示房源池、房型结构、状态筛选和楼栋维度 |
| 意愿与审核 | `prototype/review.html` | 展示多志愿、审核记录、异常状态和锁定动作 |
| 摇号控制台 | `prototype/lottery.html` | 执行四轮摇号、查看轮次结果和最终结果 |
| 通知与查询管理 | `prototype/notifications.html` | 管理短信模板、发布状态、查询入口与二维码占位 |
| 现场服务 | `prototype/onsite.html` | 演示签到核验、快速查号、打印占位和异常登记 |
| 结果与归档 | `prototype/archive.html` | 展示最终结果、候补顺序、导出占位和归档动作 |
| 住户查询页 | `prototype/query.html` | 面向住户的移动端查询入口 |

## 6. 推荐演示路径

建议按以下路径演示：

1. 从 `项目工作台` 进入当前项目，说明系统不是单页工具，而是多项目平台。
2. 在 `项目详情/阶段总览` 讲清 10 阶段时间线和活动日流程。
3. 进入 `住户管理` 与 `房源管理`，展示基础数据组织方式。
4. 在 `意愿与审核` 页面完成 `锁定名单/意愿`。
5. 进入 `摇号控制台` 执行 `A/B/C/D` 四轮摇号。
6. 在 `通知与查询管理` 页面发布结果并打开统一查询入口。
7. 用 `住户查询页` 演示查询结果同步。
8. 最后在 `结果与归档` 页面完成归档，验证只读状态。

## 7. 原型实现原则

1. 全部采用原生 `HTML / CSS / JS`，无需构建工具。
2. 通过 `localStorage` 共享当前项目与演示状态。
3. 不接真实后端，不发真实短信，不生成真实二维码。
4. 摇号结果使用固定种子的伪随机算法，保证每次重置后可复现。
5. 视觉上延续现有 `docs/*.html` 的米白、青绿、金色系与卡片化表达。
