# 项目工作流规范

状态：Accepted
适用范围：本项目及后续可复用的软件项目

## 1. 目标

建立一套轻量、可执行、可复用的软件项目工作流，让需求、方案、设计、开发、测试、发布和复盘都有固定产物和流转方式。

本规范强调：

- 先明确问题，再设计方案，再进入开发。
- 每个阶段都保留可追溯文档。
- 重要决策必须记录原因，而不只记录结论。
- 任务拆分要足够小，便于执行、评审和回滚。
- 文档服务开发，不为文档而文档。

## 2. 标准生命周期

```text
需求收集 -> 需求澄清 -> 方案设计 -> 技术设计 -> 任务拆分 -> 开发实现 -> 测试验收 -> 发布交付 -> 复盘归档
```

## 3. 阶段说明

### 3.1 需求收集

目标：记录业务方或项目自身提出的问题、目标和诉求。

输入：

- 用户描述
- 业务材料
- 原型草稿
- 会议纪要
- 现有系统问题

输出：

- `docs/01-requirements/YYYY-MM-DD-topic.md`

完成标准：

- 背景清楚
- 目标清楚
- 用户角色清楚
- 范围边界初步清楚
- 未决问题已列出

### 3.2 需求澄清

目标：把模糊诉求变成可判断是否完成的需求。

输出应包含：

- 功能需求
- 非功能需求
- 约束条件
- 验收标准
- 不做什么

完成标准：

- 每条需求都能被验证
- 关键业务流程已经闭环
- 不确定项已记录，而不是隐藏在实现里

### 3.3 方案设计

目标：在进入技术设计前，比较不同解决路径并做取舍。

输出：

- `docs/02-solutions/YYYY-MM-DD-topic-solution.md`

适用场景：

- 有多个业务流程选择
- 有多个技术选型
- 影响范围较大
- 成本、风险、体验之间需要取舍

完成标准：

- 至少说明推荐方案
- 说明为什么不选其他方案
- 明确风险和后续动作

### 3.4 技术设计

目标：把已确认方案转成可开发、可测试、可评审的技术设计。

输出：

- `docs/03-designs/YYYY-MM-DD-topic-design.md`

完成标准：

- 模块边界清楚
- 数据模型清楚
- 接口/状态流转清楚
- 异常处理清楚
- 测试策略清楚
- 关键风险清楚

### 3.5 任务拆分

目标：把设计拆成可以逐步完成、逐步验证、逐步提交的开发任务。

输出：

- `docs/04-plans/YYYY-MM-DD-topic-plan.md`
- GitHub issues

拆分原则：

- 每个任务有明确目标
- 每个任务有涉及文件
- 每个任务有验证方式
- 每个任务可以独立提交
- 优先 TDD，尤其是核心业务逻辑

### 3.6 开发实现

目标：按计划实现，并保持小步提交。

推荐流程：

1. 从 GitHub issue 创建分支。
2. 阅读对应需求/方案/设计/计划。
3. 编写测试或验收脚本。
4. 实现最小可用代码。
5. 运行验证命令。
6. 提交 commit。
7. 创建 PR。

### 3.7 测试验收

目标：证明实现满足需求，而不是只证明“代码能跑”。

输出：

- `docs/06-testing/` 下的测试策略、验收清单或测试报告

验收维度：

- 功能正确性
- 数据正确性
- 权限/安全
- 异常场景
- 兼容性
- 性能或容量，如适用

### 3.8 发布交付

目标：让版本变更、部署方式和风险透明。

输出：

- `docs/07-releases/vX.Y.Z.md`

完成标准：

- 版本内容明确
- 部署步骤明确
- 数据库变更明确
- 验证清单明确
- 已知问题明确

### 3.9 复盘归档

目标：沉淀经验，改进下一阶段工作流。

输出：

- `docs/08-reviews/YYYY-MM-DD-phase-review.md`

复盘内容：

- 原计划 vs 实际完成
- 偏差原因
- 做得好的地方
- 问题和风险
- 后续改进项

## 4. 最小必备文档集

小功能：

- 需求或 issue
- 实施计划
- 测试/验收记录

中等功能：

- 需求文档
- 方案或设计文档
- 实施计划
- PR 验证记录

重大功能或架构变更：

- 需求文档
- 方案文档
- 技术设计文档
- ADR
- 实施计划
- 测试策略
- 发布说明
- 复盘

## 5. 对本项目的应用

还房摇号系统当前处于早期阶段，优先采用以下顺序：

1. 建立文档规范和模板。
2. 整理现有需求、策划、原型、设计、计划文档。
3. 收敛 MVP 范围。
4. 将 MVP 拆成 GitHub issues。
5. 先实现后端骨架和 LotteryEngine。
6. 再从原型迁移前端页面。
