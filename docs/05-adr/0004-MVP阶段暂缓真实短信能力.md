# ADR-0004: MVP 阶段暂缓真实短信能力

状态：Accepted
日期：2026-05-11
负责人：项目维护者
关联 Issue：N/A
关联文档：
- `docs/02-solutions/2026-05-11-MVP范围方案.md`

## 背景

完整还房系统需要支持短信通知，例如活动提醒、结果通知、查询入口通知等。但真实短信能力涉及：

- 短信服务商选择
- 模板审核
- 费用控制
- 发送频率限制
- 失败重试
- 发送记录归档
- 手机号隐私和合规处理

这些内容与 MVP 的核心目标“打通摇号闭环”相关性不高，但会显著增加外部依赖和交付复杂度。

## 决策

MVP 阶段暂缓真实短信发送能力。

一期处理方式：

- 保留通知与查询的业务入口或原型展示。
- 支持导出通知名单。
- 如需演示短信，使用模拟状态或人工说明。
- 数据模型可预留通知记录扩展空间，但不接入真实短信服务商。

## 理由

- 降低 MVP 外部依赖。
- 避免短信模板审核和费用问题阻塞核心开发。
- 优先验证摇号、查询、导出和归档主流程。
- 后续真实业务明确后，再设计短信模板、发送策略和失败处理。

## 影响

### 正向影响

- MVP 更聚焦核心流程。
- 减少外部服务配置和联调成本。
- 降低早期开发复杂度。

### 负向影响

- 一期不能真实发送短信。
- 现场通知仍需要人工或导出名单辅助。
- 后续接入短信时需要补充通知服务、模板和记录表。

## 替代方案

| 方案 | 为什么没有选择 |
| --- | --- |
| MVP 直接接入真实短信 | 增加外部依赖和审核成本，不利于快速验证 |
| 完全不考虑通知模块 | 后续查询入口和结果发布体验会缺少设计衔接 |
| 使用第三方低代码短信工具 | 短期可行，但不利于系统内统一归档和审计 |

## 后续动作

- [ ] 在 MVP 中保留通知导出或模拟状态。
- [ ] 后续单独设计通知服务和短信发送记录。
- [ ] 明确短信模板、触发时机和失败重试策略。
