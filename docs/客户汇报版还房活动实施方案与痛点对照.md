# 客户汇报版还房活动实施方案与痛点对照

## 一、文档说明

`文档用途`：用于向客户汇报还房活动电子化实施思路，说明活动组织方式、系统支撑重点、客户常见顾虑及对应解决方案。  
`文档定位`：偏汇报与沟通，不替代后续详细执行手册、技术方案和现场应急预案。  
`适用阶段`：客户沟通、方案汇报、立项前交流、活动实施范围确认。  

## 二、一页式活动实施方案

### 2.1 项目定位

本方案面向 `还房活动电子化实施` 场景，目标是用 `系统集中摇号 + 现场标准化执行` 替代传统摇珠方式，在保证公平、公示、可追溯的前提下，显著提升活动效率，降低现场组织压力与争议风险。

### 2.2 活动目标

1. 用电子摇号替代传统摇珠，提升活动公信力与执行效率。
2. 把复杂的现场工作收敛为标准化流程，降低组织难度。
3. 实现名单、房源、意愿、结果的统一管理和全过程留痕。
4. 让群众看得懂规则、查得到结果、找得到依据。

### 2.3 总体思路

本次活动采用 `活动前充分确认，活动日集中摇号，活动后统一公示归档` 的组织方式。

活动当天重点完成以下事项：

1. 签到核验。
2. 规则宣讲。
3. 数据封存确认。
4. A/B/C/D 四轮摇号。
5. 结果查询。
6. 异议登记。
7. 后续办理通知。

### 2.4 五段式实施流程

#### 1. 启动准备

明确项目范围、参与对象、房源结构、房型分类、轮次规则、职责分工和活动日目标。

#### 2. 数据确认

完成有效还房户名单、房源数据、房型意愿、代理规则、异常名单的采集和核验。

#### 3. 锁定发布

在活动前完成最终名单与意愿锁定，生成参与编号，发送短信通知，准备查询二维码和现场公示材料。

#### 4. 现场执行

统一签到核验，公开宣讲规则，在监督见证下执行 A/B/C/D 四轮摇号，同步开放二维码查询，现场受理咨询和异议登记。

#### 5. 结果收尾

完成结果公示、异议复核、后续确认安排、资料导出和归档，为审计、复盘和后续办理留足依据。

### 2.5 活动日建议流程

1. `08:00-09:00` 签到核验与入场引导。
2. `09:00-09:20` 开场说明与规则宣讲。
3. `09:20-09:30` 封存数据确认。
4. `09:30-10:50` A/B/C/D 四轮摇号。
5. `10:50-11:20` 结果汇总公布。
6. `11:20-12:00` 查询辅导与异议登记。
7. `14:00-17:00` 结果确认或后续办理安排。

### 2.6 系统一期重点能力

1. 项目管理与活动配置。
2. 住户名单与资格管理。
3. 房源与房型管理。
4. 意愿填报与审核锁定。
5. 四轮摇号执行与结果生成。
6. 短信通知与二维码查询。
7. 现场快速查询与辅助服务。
8. 结果导出、公示与归档留痕。

### 2.7 方案价值

1. 把传统逐户摇珠，变成集中摇号、统一出结果。
2. 把现场拥堵与人工解释，变成扫码查询与分流服务。
3. 把靠经验组织，变成按流程执行。
4. 把事后说不清，变成全过程可追溯。

## 三、客户痛点与解决方案对照表

| 客户痛点/担忧 | 解决方案 |
| --- | --- |
| 电子摇号会不会不公平、被质疑 | 提前公示规则，活动前锁定名单、房源和意愿，现场监督见证，摇号过程留痕，结果可导出复核 |
| 现场人多，秩序不好控 | 把活动压缩成固定主流程，签到区、主会场、查询区分区组织，结果以二维码查询为主，减少围堵 |
| 数据容易出错，现场改来改去 | 活动前设置最终锁定节点，锁定后只允许异常处理，不再接受普通变更 |
| 传统摇珠太慢，一天办不完 | 改为 A/B/C/D 四轮集中摇号，现场只做核心动作，不把所有办理事项塞进主流程 |
| 群众查结果麻烦，现场咨询压力大 | 设置统一查询二维码，支持参与编号加身份校验查询，现场仅做辅导和补充查询 |
| 结果出来后如何公示、怎么留依据 | 系统统一生成结果表、候补表、导出清单和归档资料，支持后续公示与复核 |
| 万一系统或网络异常怎么办 | 准备备用电脑、备用网络、纸质台账、导出备份和人工查询口径，确保活动不中断 |
| 代理参与、补件、弃选等特殊情况怎么处理 | 提前定义异常规则和处理口径，活动前审核完成，活动日只按规则执行 |
| 客户担心系统太复杂、培训成本高 | 一期只做活动核心链路，不追求大而全，围绕名单、锁定、摇号、查询、归档五个关键动作展开 |
| 担心做完一次就没用了 | 系统按项目建设，可复用于后续多个还房项目，形成标准化模板和经验沉淀 |

## 四、对外汇报建议

在客户沟通中，建议优先讲清以下三件事，而不是一开始就讲页面和功能细节：

1. 这场活动如何从传统摇珠转为标准化电子摇号。
2. 活动当天如何更高效、更可控、更少争议。
3. 系统如何服务活动组织，而不是单独作为一个软件展示。

建议用以下表达路径与客户沟通：

1. 先讲 `活动组织方式变简单了`。
2. 再讲 `公平性、公示性、可追溯性更强了`。
3. 最后讲 `系统只是把规则和流程固化下来`。
